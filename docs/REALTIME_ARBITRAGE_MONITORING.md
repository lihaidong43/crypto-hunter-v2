# 实时套利监控使用指南

## 功能概述

实时套利监控服务会自动检测所有交易对在不同交易所之间的套利机会，包括：

- **现货-期货套利** (Spot-Futures)
- **期货-期货套利** (Futures-Futures)
- **期货-现货套利** (Futures-Spot)

当发现符合条件的套利机会时，会自动发送 Telegram 通知。

## 配置

### 1. Telegram Bot 配置

#### 创建 Telegram Bot

1. 在 Telegram 中搜索 `@BotFather`
2. 发送 `/newbot` 命令
3. 按照提示设置 bot 名称和用户名
4. 获取 bot token（格式：`123456789:ABCdefGHIjklMNOpqrsTUVwxyz`）

#### 获取 Chat ID

1. 在 Telegram 中搜索 `@userinfobot`
2. 发送任意消息，获取你的 Chat ID（数字格式）

#### 配置环境变量

在 `.env` 文件中添加：

```bash
# Telegram Bot 配置
NOTIFICATION__TELEGRAM_BOT_TOKEN=your_bot_token_here
NOTIFICATION__TELEGRAM_CHAT_ID=your_chat_id_here

# 监控配置
MONITORING__SPREAD_THRESHOLD=1.0  # 价差阈值（百分比），默认 1.0%
```

### 2. 监控参数配置

在 `.env` 文件中可以配置以下参数：

```bash
# 数据收集间隔（秒）
DATA_COLLECTION__PRICE_SYNC_INTERVAL_SECONDS=30  # 价格同步间隔，建议 30-60 秒

# 监控配置
MONITORING__SPREAD_THRESHOLD=1.0  # 价差阈值（百分比），默认 1.0%
```

**⚠️ 重要：性能考虑**

根据你的交易对数量，建议调整检查间隔：

- **交易对 < 100**：可以使用 10-15 秒间隔
- **交易对 100-500**：建议使用 30-60 秒间隔
- **交易对 > 500**：建议使用 60-120 秒间隔

**原因**：
- 每个交易对需要调用多个 API（现货价格、期货价格、资金费率）
- 每个交易所都有 API 速率限制
- 如果检查间隔太短，可能导致：
  - API 请求被限流
  - 任务堆积（上一次检查未完成，下一次就开始了）
  - 网络超时

**当前优化**：
- ✅ 分批处理：每批处理 50 个交易对，避免一次性发起太多请求
- ✅ 防重叠执行：如果上一次检查未完成，跳过本次检查
- ✅ 超时控制：每批最多 30 秒，避免长时间阻塞
- ✅ 批次间延迟：批次间有 100ms 延迟，避免 API 限制

## 运行

```bash
cargo run
```

程序启动后会自动：

1. 初始化数据库连接
2. 加载交易所适配器
3. 启动交易对收集任务（每小时同步一次）
4. 启动快照收集任务（每 5 秒收集一次价格和资金费率）
5. **启动实时套利监控服务**（每 5 秒检查一次套利机会）
6. 启动 API 服务器

## 监控逻辑

### 1. 数据收集（分批处理）

监控服务会：

- **分批处理**：将交易对分成多批（默认每批 50 个），避免 API 限制
- **并发收集**：每批内的交易对并发收集现货和期货快照
- **超时控制**：每批最多 30 秒，超时则跳过
- **批次延迟**：批次间有 100ms 延迟，避免触发 API 速率限制
- 每个快照包含：价格、资金费率、24小时交易量等信息
- 数据保存到 `market_snapshots` 表中

**示例**：如果有 862 个交易对，会分成 18 批（862 ÷ 50），每批约 30 秒，总共约 9 分钟完成一次完整检查。

### 2. 套利分析

对每个交易对，监控服务会：

- 分析所有交易所之间的套利机会
- 计算开仓价差和清仓价差
- 计算净资金费率
- 过滤出价差绝对值 >= 阈值的套利机会

### 3. 通知发送

当发现符合条件的套利机会时：

- 格式化消息并发送到 Telegram
- 同一套利机会在 5 分钟内不会重复通知（冷却时间）

### 4. 防重叠执行

- 如果上一次检查未完成，会跳过本次检查
- 避免任务堆积和资源浪费
- 日志中会显示"上一次检查尚未完成，跳过本次检查"

## 通知消息格式

```
🚨 套利机会发现

类型: 现货-期货
交易对: BTCUSDT
交易所: binance ↔ okx
价格: 50000.00 ↔ 50100.00
开仓价差: 0.2000%
清仓价差: -0.2000%
净资金费率: 0.00010000
24h交易量 A: 1000000.00
24h交易量 B: 950000.00
时间: 2024-01-01 12:00:00 UTC
```

## 价差计算公式

开仓价差公式：
```
开仓价差 = [2 × (Price_A - Price_B)] / (Price_A + Price_B) × 100%
```

清仓价差：
```
清仓价差 = -开仓价差
```

## 注意事项

1. **API 限制**：确保不要超过交易所的 API 请求频率限制
2. **网络延迟**：套利机会可能因为网络延迟而短暂存在
3. **交易成本**：实际套利需要考虑交易手续费、滑点等成本
4. **资金费率**：期货资金费率会影响套利收益，需要综合考虑

## 故障排查

### Telegram 通知未发送

1. 检查 bot token 和 chat id 是否正确
2. 确认 bot 已启动（发送 `/start` 给 bot）
3. 查看日志中的错误信息

### 未检测到套利机会

1. 检查价差阈值是否设置过高
2. 确认数据收集是否正常（查看日志）
3. 检查数据库中是否有快照数据

### 性能问题

1. 如果交易对数量很多，可以增加检查间隔
2. 考虑只监控特定的交易对（需要修改代码）
3. 检查数据库连接池配置

## 扩展

### 自定义通知格式

修改 `src/notification/telegram.rs` 中的 `format_arbitrage_message` 方法。

### 调整冷却时间

修改 `src/main.rs` 中创建 `ArbitrageMonitor` 时的 `notification_cooldown_seconds` 参数。

### 添加更多过滤条件

在 `src/monitor/arbitrage_monitor.rs` 的 `check_all_opportunities` 方法中添加更多过滤逻辑。
